# PDF 中文补译与全书对照审校

## 适用范围与默认要求

当用户要求继续翻译 PDF、补齐中文版、按原版恢复删页／图例，或审校已有翻译时使用。本 skill 是代理执行流程，附带辅助脚本；脚本不会自行理解、翻译或审核全文。

优先遵循当前用户要求。默认准确、自然地翻译全部叙述性文字；技术术语采用 `English（中文译名）`，缩略语按语境保留。默认中文字体为 Source Han Sans SC（思源黑体），常规与粗体分别嵌入；用户另指定字体时替换。

“保留 PDF 样式”指保留页面顺序、尺寸、图片、线条、表格、图例对应关系、颜色及布局；翻译必然改变输出文件的文本对象。保留原文件，另存最终结果。不要把全文转成图片，不要将整页当作图片编辑。

当前会话已授权的操作直接继续。通过服务插件读取用户指定文件，工具足够时不用浏览器。外部翻译仅在现有授权涵盖该服务及文本披露时使用；一个项目的外发许可不自动成为其他项目的许可。不要求用户重复确认已授权的步骤；不主动发送邮件或消息。

如果只有英文原档而没有已有中文版，以完整英文原页作为布局基线，将全部待翻译单元标为新译；其余排版、全书对照和交付检查仍适用。

## 1. 建立项目与可恢复记录

先发现并读取环境内适用的 AGENTS.md，确认可用 PDF 库、字体和存储空间。优先 Python + PyMuPDF；按需使用 fontTools、Pillow 和 OCR。

从 `templates/project.example.json` 建立项目配置。记录：

- 全部原档、未完成中文版、已有输出的路径、页数和 SHA-256。
- 多份原档的卷序与合订页码范围；建立显式 `page_map.json`，不用“第一个文件就是上卷”这种假设。
- 最新用户要求：字体、术语格式、版式约束、是否全文审校、交付位置。
- 外部翻译许可的适用范围，若未使用则记录未使用。

建议目录：`source/`、`work/`、`fonts/`、`review/`、`qa/`、`deliverables/`。每阶段生成文件与日志，不依赖聊天记录恢复。不要复制本案例的文件名、Drive ID、总页数或参数到新项目。

运行 `scripts/pdf_localize.py inspect` 建立清单，`extract` 导出带坐标的文字。所有脚本路径以本 skill 所在目录解析。

## 2. 以英文原页建立完整性基准

逐页比较英文原版和中文版。既检查正文，也检查整页、截图、图例、表格、页眉页脚、脚注、公式、参考资料、目录和书签。不能仅比较可提取的字符数。

为每页标注：完整保留／部分缺译／节译／整页缺失／图形缺失／疑似错位／需要 OCR。英文原页是图片与布局基准；中文原页是既有译文和已认可样式的参考。

对删页、图片缺失或结构损坏的页面，先以对应英文原页恢复页面骨架，再把完整中文文本放回原文本区域。保留合订本的链接与书签映射。不要在缺图的中文版上只补几段文字就视为恢复完成。

PDF 的 rotation、cropbox 和文字坐标可能不同。用临时副本统一坐标后比较，输出采用既定页面方向；不得全局强制所有 PDF 旋转归零。

## 3. 提取、匹配与判断漏译

建立稳定文字单元：`id`、合订页码、英文、原矩形、容器矩形、字号、颜色、粗体、方向、行／span。中文版另存实际文字与矩形。使用页内几何位置、段落语义、章节和数字进行匹配。

不要把 PDF 的每个视觉换行当成语义换行。空译文可能已并入相邻单元；一个中文文本框也可能覆盖多个英文单元，必须看原页确认。不得因匹配失败直接删除附近中文。

抽取乱码先解决字体／编码，不能拿乱码做翻译。图片内文字单独 OCR 并人工校正；实物铭牌、游戏界面标签、设备代码默认保留英文以便操作对应，周围说明应中文化。需要翻译的图片图例应单列处理，不得改变图像、箭头、颜色或编号。

输出 `review/units.json` 与 `review/page_status.json`。单元至少包括 `id, page, source, zh, status`。`status` 应区别已有译文、新补译、保持原文、待核实及完成审校。

## 4. 翻译和术语统一

先建立 `glossary.json`，再分批处理。`batches` 命令只生成对照审校包，绝不替代审校。

- 按完整语义翻译，保留条件、否定、时间顺序、责任主体、限制、数量、单位、警告和操作结果。
- 不写摘要代替原文，不把详细步骤改成“系统会提示”等泛化句。
- 原译已有节译时，以完整英文重译该单元并替换。
- 术语按专业语境判断，不能全局盲替换。具体航空示例见 `references/aviation-examples.md`；其他行业另建术语表。
- 仅对语义和用途一致的重复英文传播译文。保留逐单元覆盖项；记录冲突，检查后处理。
- 型号、呼号、键位、频率、代码、正负号、小数及单位逐项核对；`nm` 不可译成“纳米”。数字相同只是线索，不是正确性证明。
- 原文疑似事实错误、单位自相矛盾时，核对上下文和可靠原始手册。不能悄悄编造修正；必要时忠实翻译并用简短译注标明。

将审核后的完整译文写入 `patches.json`。术语表修订后，检查正文、图例、目录、书签与重复标题的一致性。

## 5. 写回文本，保留原图形

在最新完整基线的副本上修改，不要回到早期阶段版而丢失图例、公式或链接修复。使用 `templates/patches.example.json` 的显式几何清单。

先渲染代表页验证正文、短标签、表格、标题、竖排、红色警告及公式，再批量输出。

附带 `apply` 命令只替换已经人工确认的文本框：

- 预先检查字体覆盖和所有文字能否在最小字号限制内放入；放不下就失败，不偷偷截断或缩成难读小字。
- 仅移除目标文字：`apply_redactions(images=0, graphics=0)`。不要用白色块遮住未知图形。
- 先保存并移除该页链接，再执行文本 redaction，最后恢复链接，避免链接缓存错误及隐性丢失。
- 中文按字符、英文按词换行；按原文颜色、粗体和方向排版。章节标题保留语义分行。
- 小框过长时，先检查多余双语重复和安全留白；不能删掉信息以硬塞。需要不同层级字号／上下标的公式，单独排版并校对。

字号下限由文档决定：正文通常至少 8 pt，密集原版检查单可能更小但必须明确记录并放大检查。不能把“脚本 fit 成功”当成排版合格。

## 6. 必须覆盖已有译文的全文审校

用户要求“全部检查”时，把原有译文和本次补译一同对照英文。不要只核对新翻译的页面。

分别维护三份记录：

1. **文字记录**：每个语义单元是否已对照、问题和修订、术语与数字核对结果。
2. **逐页记录**：每页图片、图例、结构、排版检查结果；修改页再次渲染；缩略接触表看整体，放大图看文字、箭头端点、表格边界和公式。
3. **结构记录**：页码与尺寸、图片数量／尺寸／位置、链接完整目标、书签层级及目标、字体覆盖与占位标记。

自动审计只能证明它实际检查的项目。`audit` 不会判断语义、发现所有漏译、验证数学或证明矢量图逐像素一致。只有文字逐单元审校记录和全页检查记录均闭合，才能报告“全文对照审校完成”。

本轮发现系统性误译时，搜索全书及书签，不只修当前一页。修订后再检查受影响页面，保留未解决问题清单，不能自动标记通过。

## 7. 最终校验和交付

先对最新完整基线运行 `audit --reference ...`，验证改译过程没有损伤图片、链接或书签。若基线曾缺图，还应按 `page_map.json` 对英文原档另做完整性核对。不要把缺图基线本身当作唯一正确标准。

导出完整合订本，并按实际上传工具限额生成分册。分册应调整书签为册内页码；跨册跳转限制须在说明中写清。不得为上传方便有损压缩原图而不告知。

交付：最终 PDF、可选分册、简短核对说明和 SHA-256。已授权更新 Drive 时优先原文件 ID 更新内容，检查远端名字、大小和目标目录。未授权替换时另存新文件，不覆盖原档。

最终回复用用户的语言，提供真实可下载链接，简述实际审校范围和保留结果。没有完成全部审校时必须说清已完成范围，不使用“零错误”“百分之百准确”等无法证明的保证。

## 附带工具

- `scripts/pdf_localize.py`：清单、带坐标提取、审校分批、受控文本写回、结构审计。
- `scripts/self_test.py`：以合成 PDF 验证写回和链接／图片／书签保留；不接触用户原档。
- `references/implementation-notes.md`：排版、字体和实际故障处理。
- `references/aviation-examples.md`：本案例抽象出的术语陷阱，不能当作跨行业替换表。

Python 依赖：`pip install -r scripts/requirements.txt`。有可用依赖时不重复安装。具体命令见包内 `README.md`。
